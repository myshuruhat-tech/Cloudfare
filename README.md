# 5AL — Android / Android TV (يشتغل أوفلاين)

التطبيق يفتح موقعك على Cloudflare (live-screen.myshuruhat.workers.dev) لما فيه إنترنت، ولما ما فيه
يقدّم النسخة المضمّنة داخل الـ APK (app/src/main/assets/web) بنفس الـ origin، فتظهر التنزيلات
والسجل والحسابات (IndexedDB / localStorage) كما هي.

## البناء
1. Android Studio -> Open -> هذا المجلد -> انتظر Gradle Sync.
2. Build -> Build APK(s) -> app/build/outputs/apk/debug/app-debug.apk

## تحديث النسخة المضمّنة
تلقائي: كل مرة يفتح التطبيق بإنترنت يحفظ آخر index.html و app.html والخط من الموقع لاستخدامه أوفلاين.
ما تحتاج تعيد بناء الـ APK مع كل نشر. (النسخة داخل الـ APK = v141، احتياط فقط.)

## مهم
- افتح التطبيق مرة واحدة بالإنترنت قبل الأوفلاين (ليحفظ نسخة hls.js داخل التطبيق).
- لو الأندرويد رفض التثبيت فوق القديم (توقيع مختلف) لازم حذف القديم، وحذفه يمسح التنزيلات.

## البناء من GitHub (بدون Android Studio)
1. أنشئ مستودع **Private** جديد على GitHub.
2. ارفع كل محتويات هذا المجلد (مع مجلد .github المخفي) في الجذر.
3. تبويب Actions -> Build APK -> انتظر ~5 دقائق -> نزّل LiveScreenTV-apk من Artifacts (zip فيه app-debug.apk).
التوقيع ثابت (app/livescreen.keystore) فكل نسخة جديدة تتثبّت فوق السابقة بدون حذف.

## تحليل واجهة التصويت (من لقطات Kick الحية)
- التوقع: بطاقة بالشات (سؤال + `0 vs 0` + زر Predict + ⋮ فيه Learn more/Dismiss). لوحة Predictions: سؤال، `N points contributed`، نسبة `X% vs Y%`، Options (رقم + نص + نقاط + نسبة مثل 1:0*)، حقل Prediction Amount، Your balance، Prediction closes in mm:ss، زر Predict.
- بعد التوقع: الرصيد ينقص، الخيار الثاني يتعطل (ما تغيّر الجهة)، تقدر تزيد على نفس الخيار. أخطاء: `Please select an outcome` و`You don't have enough balance to predict`.
- بعد القفل: Predict يصير See details، لوحة بعنوان Outcomes وفيها Winner ✓ ونسبة (1:1.0). Start new prediction/Cancel لصاحب القناة فقط.
- الاستطلاع: Current poll + سؤال + صفوف (نص، النسبة، العدد)، الضغط على الصف يصوّت مباشرة (✓ على اختيارك)، شريط أخضر وقت متبقي، ↑ يطوي. بعد الانتهاء: Poll ended والفائز أخضر كامل.
- المثبتة: Sent by + المرسل + نص مقتطع بـ… و⌄/⌃ للتوسيع، العين المشطوبة تخفي كل البطاقات ويبقى زر 📌 يرجعها.
- ترتيب البطاقات: توقع، مثبتة، استطلاع.
- قرار: نصمم شكل العرض بتطبيقنا (ما نقلّد تحويل البطاقة).
- (v6+) votescan.js صار يلتقط: poll/ended، predict، predend (Outcomes)، predcard، pinned، banner، وأزرار الأيقونات بلا نص (icons) لنعرف زر العين والدبوس. المطلوب: ظهور المربع الأخضر مع توقع/استطلاع/مثبتة حية وإرسال الناتج.
- لسا ما انكتبت واجهة التصويت. الخطوة التالية: تحليل ناتج الالتقاط ثم بناء البطاقة.
